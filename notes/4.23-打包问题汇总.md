这是 **Windows 路径空格/中文导致的 pip 构建失败**。

## 根因

你的项目路径是：
```
F:\1\ai-novelist - 副本\qingzhu
```

路径中包含**空格**和**中文**，当 pip 安装需要从源码构建（含 `pyproject.toml`）的包时，其内部构建后端生成的 Windows 命令在拼接路径时未正确加引号，导致路径被截断。例如 `cd F:\1\ai-novelist - 副本\...` 被错误解析，`cd` 只接收到 `F:\1\ai-novelist`，剩下的 `- 副本\...` 被当成额外参数，Windows 尝试访问以 `-` 开头的"目录"，于是抛出 [`WinError 267`](launcher/internal/backend/backend.go:52)「目录名称无效」。

## 解决

**立即解决**：将项目目录移动到不含空格和中文的路径，例如：
```
F:\ai-novelist\qingzhu
```

然后重新启动即可。

这是一个 **pip 依赖解析冲突** 报错，问题的核心不是 `langchain-chroma` 和 `chromadb` 之间的冲突，而是 **`mmh3` 这个包在当前环境中无法安装**。

### 报错原因

`langchain-chroma==1.1.0` 依赖 `chromadb`，而 `chromadb` 的几乎所有版本都依赖 `mmh3>=4.0.1`。

pip 在解析依赖时尝试了 `chromadb` 的多个版本（从 `1.5.8` 到 `1.3.5`），发现每个版本都需要 `mmh3>=4.0.1`，但当前环境无法满足这个条件。

在 Windows 上，`mmh3` 是一个包含 C/C++ 代码的 Python 包，如果：
- 当前 Python 版本没有对应的预编译 wheel（whl）
- 或者环境中没有安装 Visual C++ Build Tools 等编译工具

pip 就会无法安装 `mmh3`，最终导致依赖解析失败。

### 解决方案

#### 方案 1：手动安装预编译的 mmh3（最快）

先手动安装 `mmh3` 的预编译版本，再重新启动部署：

```powershell
F:\1\0.2.0\qingzhu\.venv\Scripts\python.exe -m pip install mmh3
```

安装成功后，再用启动器重新部署。

#### 方案 2：升级 pip（可能解决 wheel 选择问题）

报错信息里也有提示，先升级 pip：

```powershell
F:\1\0.2.0\qingzhu\.venv\Scripts\python.exe -m pip install --upgrade pip
```

升级后再重新启动部署。

#### 方案 3：如果 mmh3 编译失败，安装编译工具

如果手动安装 `mmh3` 提示缺少编译器，需要安装 Visual C++ Build Tools：

```powershell
winget install Microsoft.VisualStudio.2022.BuildTools --override "--wait --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

#### 方案 4：检查 Python 版本兼容性

如果上述方法都无效，可能是当前 Python 版本（比如非常新的 3.13 或很老的 3.8）缺少 `mmh3` 的预编译包。可以尝试更换 Python 版本（推荐 3.10 - 3.12），删除 `.venv` 后重新部署。

---

**建议先尝试方案 1 + 方案 2**，即先升级 pip，再手动安装 mmh3，最后重新用启动器部署。
