这是 **Windows 路径空格/中文导致的 pip 构建失败**。

## 根因

你的项目路径是：
```
F:\1\ai-novelist - 副本\qingzhu
```

路径中包含**空格**和**中文**，当 pip 安装需要从源码构建（含 `pyproject.toml`）的包时，其内部构建后端生成的 Windows 命令在拼接路径时未正确加引号，导致路径被截断。例如 `cd F:\1\ai-novelist - 副本\...` 被错误解析，`cd` 只接收到 `F:\1\ai-novelist`，剩下的 `- 副本\...` 被当成额外参数，Windows 尝试访问以 `-` 开头的"目录"，于是抛出 [`WinError 267`](launcher/internal/backend/backend.go:52)「目录名称无效」。

## 解决

**立即解决**：将项目目录移动到不含空格和中文的路径，例如：
```
F:\ai-novelist\qingzhu
```

然后重新启动即可。

这是一个 **pip 依赖解析冲突** 报错，问题的核心不是 `langchain-chroma` 和 `chromadb` 之间的冲突，而是 **`mmh3` 这个包在当前环境中无法安装**。

### 报错原因

`langchain-chroma==1.1.0` 依赖 `chromadb`，而 `chromadb` 的几乎所有版本都依赖 `mmh3>=4.0.1`。

pip 在解析依赖时尝试了 `chromadb` 的多个版本（从 `1.5.8` 到 `1.3.5`），发现每个版本都需要 `mmh3>=4.0.1`，但当前环境无法满足这个条件。

在 Windows 上，`mmh3` 是一个包含 C/C++ 代码的 Python 包，如果：
- 当前 Python 版本没有对应的预编译 wheel（whl）
- 或者环境中没有安装 Visual C++ Build Tools 等编译工具

pip 就会无法安装 `mmh3`，最终导致依赖解析失败。

### 解决方案

#### 方案 1：手动安装预编译的 mmh3（最快）

先手动安装 `mmh3` 的预编译版本，再重新启动部署：

```powershell
F:\1\0.2.0\qingzhu\.venv\Scripts\python.exe -m pip install mmh3
```

安装成功后，再用启动器重新部署。

#### 方案 2：升级 pip（可能解决 wheel 选择问题）

报错信息里也有提示，先升级 pip：

```powershell
F:\1\0.2.0\qingzhu\.venv\Scripts\python.exe -m pip install --upgrade pip
```

升级后再重新启动部署。

#### 方案 3：如果 mmh3 编译失败，安装编译工具

如果手动安装 `mmh3` 提示缺少编译器，需要安装 Visual C++ Build Tools：

```powershell
winget install Microsoft.VisualStudio.2022.BuildTools --override "--wait --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

#### 方案 4：检查 Python 版本兼容性

如果上述方法都无效，可能是当前 Python 版本（比如非常新的 3.13 或很老的 3.8）缺少 `mmh3` 的预编译包。可以尝试更换 Python 版本（推荐 3.10 - 3.12），删除 `.venv` 后重新部署。

要在自动安装脚本中勾选 “Use admin privileges when installing py.exe” 这个选项，对应的命令行参数是 InstallLauncherAllUsers=1（同时配合 Include_launcher=1）。
🔍 参数说明
核心参数：InstallLauncherAllUsers=1这个参数的作用是为所有用户安装 py.exe（Python Launcher），安装过程需要管理员权限，和界面上的 “Use admin privileges when installing py.exe” 完全对应。
必须同时配合 Include_launcher=1（默认就是 1，一般不用额外写，但写上去更稳妥）。
它的本质是把 py.exe 安装到系统目录（C:\Windows\），而不是当前用户目录，所以需要管理员权限写入。
完整的静默安装示例如果你要在脚本里实现勾选这两个选项（加上环境变量），可以用下面的命令：
bash
运行
python-3.x.x-amd64.exe /quiet InstallLauncherAllUsers=1 PrependPath=1 Include_launcher=1
/quiet：静默安装，不显示界面。
PrependPath=1：对应界面上的 “Add python.exe to PATH”，把 Python 添加到环境变量。
InstallLauncherAllUsers=1：勾选 “Use admin privileges when installing py.exe”。
注意事项
这个安装脚本必须以管理员身份运行，否则 InstallLauncherAllUsers=1 会失败。
如果不想用管理员权限，可以把 InstallLauncherAllUsers=0，但此时界面上的选项就会变成不勾选状态。
💡 补充：界面上的 “Use admin privileges when installing py.exe”，本质就是 “Install launcher for all users” 的权限提示，所以命令行里直接用 InstallLauncherAllUsers=1 就能实现勾选效果。

但是我们在win + i搜索应用时，确实安装了python


根本原因：Windows 的 App Execution Alias 会在 %USERPROFILE%\AppData\Local\Microsoft\WindowsApps 下创建 python.exe 和 python3.exe 的"假"入口，它们指向微软商店。即使你安装了真正的 Python，如果这个别名存在且 PATH 优先级更高，python 命令就会触发"请从微软商店安装"的提示。


注册表里有！Python 实际安装在 `F:\1\0.2.0\qingzhu\bin\python\`。这说明之前启动器已经成功安装过便携版 Python 了。

现在理清思路：`CheckSystemPython()` 的用途是检测系统是否有可用的 Python，如果有就用它，没有就走 `EnsurePython()` 下载安装。但当前的问题是：

1. `exec.LookPath("python")` 找到了 WindowsApps 的假 python.exe
2. 执行 `python --version` 失败（因为别名指向商店空壳）
3. 于是认为"无法获取 Python 版本信息"，走 `EnsurePython()` 下载安装
4. 但 Python 其实已经安装过了（在 `F:\1\0.2.0\qingzhu\bin\python\`）

最佳方案：修改 `CheckSystemPython()`，让它不仅查 PATH，还查注册表和常见安装路径。

问题在于：**之前已经通过这个安装器安装过一次 Python 到 `F:\1\0.2.0\qingzhu\bin\python\`**，注册表里已经有记录。再次运行安装器时，Burn（WiX 的引导程序）检测到已安装的旧版本，尝试先卸载再安装，但卸载过程失败了（`0x80070643`）。

## 解决方案

修改 [`EnsurePython()`](launcher/internal/env/env.go:47)，添加 `InstallAllUsers=0`（当前用户安装，避免权限问题）和 `/norestart`，同时关键的是加上 `SimpleInstall=1` 跳过 Burn 的复杂依赖检测：

改动在 [`launcher/internal/env/env.go`](launcher/internal/env/env.go:158) 的 `EnsurePython()` 函数中，安装参数改为：

| 参数 | 值 | 说明 |
|------|----|------|
| `/passive` | — | 静默安装，仅显示进度条 |
| `/norestart` | — | 安装后不重启 |
| **`SimpleInstall=1`** | ✅ **新增** | **跳过 Burn 的复杂依赖检测，直接覆盖安装，避免旧版本 MSI 卸载失败** |
| `TargetDir=...` | 指定目录 | 安装到 `bin/python/` |
| `PrependPath=1` | ✅ | 添加到 PATH |
| `AssociateFiles=0` | ❌ | 不关联 .py 文件 |
| `InstallLauncherAllUsers=0` | ❌ | 不安装全局 launcher |
| `Include_launcher=0` | ❌ | 不安装 py.exe |

核心改动就是用 `SimpleInstall=1` 替代了之前的 `InstallAllUsers=1` + `InstallLauncherAllUsers=1` + `Include_launcher=1`，这样安装器不会尝试卸载旧版本，而是直接覆盖安装，彻底避免 `0x80070643` 卸载失败的问题。

这是 Windows Defender SmartScreen 触发的安全提示，我来给你拆解一下这个报错的完整含义和处理方式👇
🔍 这个报错到底是什么？
完整的提示内容是：
Windows 已保护你的电脑Microsoft Defender SmartScreen 阻止了无法识别的应用启动。运行此应用可能会导致你的电脑存在风险。
它的本质是：
这不是病毒或木马的直接查杀，而是 SmartScreen 的「未知发布者 / 低信誉程序」拦截。
SmartScreen 会通过微软的云端数据库，检查程序的数字签名、下载来源和用户信誉。如果程序没有有效数字签名、或者下载量 / 用户反馈很低，就会触发这个蓝色弹窗，防止你误运行恶意软件。
🛡️ 为什么会出现这个提示？
常见原因有这几种：
程序没有数字签名，或签名不受信任：很多个人开发、小众工具、破解软件、汉化工具，都没有正规厂商的数字签名，会被直接判定为 “无法识别”。
程序是刚发布的，用户量太少：微软的云端数据库里，还没有足够的用户数据证明它是安全的，就会触发保护。
程序来自不常见的下载渠道：比如小众论坛、网盘分享，而不是官方网站或微软商店，也更容易被拦截。
程序本身确实存在风险：也有可能它就是病毒、恶意软件，SmartScreen 帮你拦下来了。
✅ 安全的处理方法（分情况）
情况 1：你确认这个程序是安全的（比如自己写的工具、官网下载的小众软件）
可以手动放行：
点击弹窗里的 「更多信息」，会出现隐藏的「仍要运行」按钮。
点击「仍要运行」，程序就会正常启动了。
情况 2：你不确定程序是否安全
绝对不要强行运行！ 建议：
先通过杀毒软件全盘扫描，或者上传到 VirSCAN 等在线多引擎杀毒平台检测。
优先去程序的官方网站，重新下载带正规数字签名的版本。
对于破解、汉化、来源不明的程序，直接删除，避免中招。
⚠️ 不推荐的 “一劳永逸” 操作
很多人会直接在 Windows 安全中心里关闭 SmartScreen，这会让你的电脑失去一层重要的防护，不建议这么做。它的存在能帮你挡住绝大多数恶意软件，只有在你完全确认安全的单个程序上，才临时放行即可。
💡 补充一个小知识：SmartScreen 是 Windows 自带的免费防护功能，它和 Windows Defender 杀毒引擎是配合工作的，一个负责程序信誉检查，一个负责病毒查杀，两者缺一不可。

要让你写的程序不被 Windows SmartScreen 拦截，核心思路是让程序获得 “可信” 的身份和足够的用户信誉，而不是单纯绕过它。下面给你一套从「基础到进阶」的完整方案，按推荐优先级排序👇
一、最稳妥：给程序加上「数字签名」（强烈推荐）
这是解决拦截问题的根本方法，也是微软最认可的方式。
1. 原理
SmartScreen 会优先检查程序是否有有效、可信的数字签名，只要签名合法，程序会被直接放行，不会触发蓝色弹窗。
2. 签名的两种方式
表格
方式	说明	成本	效果
代码签名证书（EV 或普通）	从权威 CA（如 DigiCert、 Sectigo）购买的正规证书	几百到几千元 / 年	100% 消除拦截，长期有效，是企业级标准方案
自签名证书	自己用工具生成的证书	免费	仅在你的电脑上信任，发给用户无效，无法绕过 SmartScreen
3. 给程序签名的操作步骤（Windows 自带工具）
购买并导入 CA 颁发的代码签名证书（.pfx 格式文件）
打开命令提示符（管理员），用 signtool 工具签名：
bash
运行
signtool sign /f "你的证书.pfx" /p "证书密码" /t http://timestamp.digicert.com "你的程序.exe"
/t 是时间戳地址，必须加上，否则证书过期后程序会失效
签名完成后，右键程序 → 属性 → 数字签名，就能看到你的签名信息
二、次选：提升程序的「用户信誉」
如果暂时不打算买证书，可以通过以下方式让程序慢慢被微软的云端数据库标记为安全：
1. 从官方渠道发布，积累下载量
把程序发布在官网、GitHub Releases、微软商店等正规平台，避免网盘、论坛等小众渠道
让足够多的用户下载、运行，并且没有安全反馈（比如被 Defender 查杀），SmartScreen 的拦截概率会随着用户量增加而大幅降低
2. 完善程序的「文件信息」
SmartScreen 也会参考程序的文件元数据，空白信息更容易被判定为 “可疑程序”：
给程序添加版本信息、公司名称、版权声明
以 C#/C++ 为例，在项目属性里填写：
程序集名称、版本号
公司名称、产品名称、版权信息
编译时选择「发布模式」，不要用 Debug 模式发给用户
3. 避免触发可疑行为
SmartScreen 会通过程序行为判断风险，这些行为会大幅提高拦截概率：
程序修改系统文件、注册表、开机启动项
程序解压 / 释放其他文件到系统目录
程序连接未知的外部网络地址
程序加壳、混淆（尤其是冷门 / 未广泛使用的加壳工具）
三、给用户的临时放行方案（当拦截已经发生时）
如果用户运行你的程序时还是触发了弹窗，可以教他们手动放行，步骤非常简单：
在蓝色弹窗上点击 「更多信息」（这个按钮默认是隐藏的）
下方会出现 「仍要运行」 按钮，点击即可启动程序
第一次放行后，同一台电脑后续再运行就不会再拦截了
四、不推荐的 “偏方”（有坑，谨慎使用）
这些方法虽然能绕过拦截，但会带来额外的问题，不建议作为常规方案：
用压缩包 / 安装包分发：把 exe 打包成 zip 或 exe 安装包，部分情况下能降低拦截概率，但治标不治本，且安装包本身也可能被拦截
用流行的安装工具打包：比如 Inno Setup、NSIS 等正规安装包制作工具，比直接分发裸 exe 更不容易被拦截，但还是不如数字签名稳妥
让用户关闭 SmartScreen：会降低用户电脑的安全性，也会让你的程序看起来更像恶意软件，不建议引导用户这么做
五、避坑指南：这些操作会让拦截更严重
用破解 / 盗版的加壳工具、混淆器
程序没有任何版本信息、文件描述
从个人网盘、非正规论坛发布程序
频繁修改程序，发布大量不同版本的 exe
程序被用户举报为恶意软件，或者被 Defender 查杀过
💡 总结一下：长期来看，买一张代码签名证书是性价比最高的方案，不仅能解决拦截问题，还能提升用户对你程序的信任度。如果是个人开发者，预算有限的话，可以先通过完善程序信息、正规渠道发布、积累用户量的方式降低拦截概率。
