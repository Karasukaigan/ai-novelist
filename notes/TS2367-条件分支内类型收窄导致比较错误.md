# TS2367: 条件分支内类型收窄导致比较错误

## 问题现象

```ts
const [tab, setTab] = useState<'launcher' | 'git'>('launcher');

// ...

{tab === 'launcher' ? (   // ← 此处将 tab 收窄为 "launcher"
  <>
    <button className={`tab-btn ${tab === 'git' ? 'active' : ''}`} />  // ← TS2367 错误
  </>
) : (
  <GitManager />
)}
```

TypeScript 报错：
```
error TS2367: This comparison appears to be unintentional because the types '"launcher"' and '"git"' have no overlap.
```

## 根本原因

TypeScript 的控制流分析（Control Flow Analysis）会在条件分支内收窄变量类型：

1. `tab === 'launcher'` 为 `true` 的分支内，`tab` 的类型被收窄为 `"launcher"`
2. 在该分支内比较 `tab === 'git'`，TypeScript 判定 `"launcher"` 和 `"git"` 没有重叠，永远为 false
3. 这不是 `useState` 泛型推断的问题，也不是 TypeScript 版本的问题

## 修复方案

**将 tab 切换按钮移到条件分支外部**，只有内容区保留在条件分支内：

```tsx
<>
  {/* 工具栏（含 tab 切换按钮）始终渲染 */}
  <div className="toolbar">
    <div className="tabs">
      <button className={`tab-btn ${tab === 'launcher' ? 'active' : ''}`}>启动器</button>
      <button className={`tab-btn ${tab === 'git' ? 'active' : ''}`}>Git管理</button>
    </div>
  </div>

  {/* 只有内容区根据 tab 切换 */}
  {tab === 'launcher' ? (
    <LogBox />
  ) : (
    <GitManager />
  )}
</>
```

## 教训

- 当 TS2367 报类型不重叠时，先检查代码是否在某个条件分支内部
- `useState` 的泛型声明和 TypeScript 版本通常不是这类问题的原因
- 控制流分析导致的类型收窄是 TypeScript 的正常行为，不是 bug
- 修复时应考虑代码逻辑是否正确（本例中 tab 按钮在条件分支内导致切换到 git 后工具栏消失，无法切回）
