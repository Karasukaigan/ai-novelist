解决方案是类似这个脚本的逻辑：

没有依赖 Scripts/pip.exe，而是始终使用 python -m pip，并且通过 --target 参数把包安装到指定目录。更重要的是，它创建了一个 启动.bat，其中设置了 PYTHONPATH 环境变量


脚本安装的 pip 能跨系统使用，核心在于**它根本不依赖 `Scripts/pip.exe`**。

脚本后续调用的是：
```powershell
& "$OutputDir\python\python.exe" -m pip install --target=...
```

这避开了 `pip.exe` 里的绝对路径 shebang，直接通过 `python -m pip` 调用 `Lib/site-packages/pip/` 里的纯 Python 代码。

`Lib/site-packages/pip/` 这个目录本身**不含任何硬编码的绝对路径**，复制到任何 Windows 电脑的相同相对位置下，`python -m pip` 都能正常工作。

真正含绝对路径的只有 `Scripts/pip.exe`（由 distlib 生成的 launcher stub），而脚本**从未调用它**。

所以你的启动器也应该采用同样的策略：
1. 打包时预装 pip（保留 `Lib/site-packages/pip`，可删掉 `Scripts/pip.exe`）
2. 运行时始终用 `python -m pip --target=xxx` 安装依赖
3. 通过环境变量 `PYTHONPATH` 或 `.pth` 让 Python 找到这些包

#!/usr/bin/env pwsh
# 构建后端便携 Python 环境

param([string]$PythonVersion = "3.13.9")
$ErrorActionPreference = "Stop"

$ProjectRoot = Split-Path -Parent $PSScriptRoot
$OutputDir = "$ProjectRoot\dist\portable"

Write-Host "=== 构建后端便携环境 ===" -ForegroundColor Green
Write-Host "Python 版本: $PythonVersion" -ForegroundColor Cyan

# 清理
if (Test-Path $OutputDir) {
    Remove-Item -Recurse -Force $OutputDir
}
New-Item -ItemType Directory -Force -Path $OutputDir | Out-Null

# 下载 Python
$PythonUrl = "https://www.python.org/ftp/python/$PythonVersion/python-$PythonVersion-embed-amd64.zip"
$PythonZip = "$OutputDir\python.zip"
Write-Host "[1/4] 下载 Python..." -ForegroundColor Yellow
Invoke-WebRequest -Uri $PythonUrl -OutFile $PythonZip -UseBasicParsing

# 解压
Write-Host "[2/4] 解压 Python..." -ForegroundColor Yellow
Expand-Archive -Path $PythonZip -DestinationPath "$OutputDir\python" -Force
Remove-Item $PythonZip

# 配置 .pth 文件
$pthFile = Get-ChildItem "$OutputDir\python" -Filter "python*._pth" | Select-Object -First 1
if ($pthFile) {
    (Get-Content $pthFile.FullName) -replace '^#import site', 'import site' | Set-Content $pthFile.FullName
}

# 安装 pip
Write-Host "[3/4] 安装 pip..." -ForegroundColor Yellow
$GetPip = "$OutputDir\get-pip.py"
Invoke-WebRequest -Uri "https://bootstrap.pypa.io/get-pip.py" -OutFile $GetPip -UseBasicParsing
& "$OutputDir\python\python.exe" $GetPip --no-warn-script-location --quiet
Remove-Item $GetPip

# 配置 VS 环境
Write-Host "[3.5/4] 配置编译环境..." -ForegroundColor Yellow
$vsPaths = @(
    "${env:ProgramFiles}\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat",
    "${env:ProgramFiles}\Microsoft Visual Studio\2022\Community\VC\Auxiliary\Build\vcvars64.bat"
)
foreach ($path in $vsPaths) {
    if (Test-Path $path) {
        cmd /c "`"$path`" && set" | ForEach-Object {
            if ($_ -match "^(.+?)=(.+)$") {
                [Environment]::SetEnvironmentVariable($matches[1], $matches[2], "Process")
            }
        }
        $env:DISTUTILS_USE_SDK = "1"
        Write-Host "  已配置: $path"
        break
    }
}

# 安装依赖
Write-Host "[4/4] 安装依赖..." -ForegroundColor Yellow
& "$OutputDir\python\python.exe" -m pip install `
    --target="$OutputDir\python\Lib\site-packages" `
    scikit-build-core cmake setuptools wheel --quiet

& "$OutputDir\python\python.exe" -m pip install `
    --target="$OutputDir\python\Lib\site-packages" `
    -r "$ProjectRoot\backend\requirements.txt" --quiet

# 复制项目文件
Copy-Item "$ProjectRoot\main.py" $OutputDir
Copy-Item -Recurse "$ProjectRoot\backend" $OutputDir
Copy-Item -Recurse "$ProjectRoot\static" $OutputDir
Copy-Item "$ProjectRoot\.env.example" $OutputDir

# 创建启动脚本
@"
@echo off
set PYTHONPATH=%~dp0python\Lib\site-packages
%~dp0python\python.exe %~dp0main.py
"@ | Set-Content "$OutputDir\启动.bat" -Encoding UTF8

$size = [math]::Round((Get-ChildItem $OutputDir -Recurse | Measure-Object -Property Length -Sum).Sum / 1MB, 2)
Write-Host ""
Write-Host "=== 后端构建完成 ===" -ForegroundColor Green
Write-Host "输出: $OutputDir" -ForegroundColor Cyan
Write-Host "大小: $size MB" -ForegroundColor Cyan

## 一、完整流程与每一步做了什么

### 步骤 1：下载并部署 Python 嵌入版

嵌入版 Python（`python-3.13.9-embed-amd64.zip`）是官方提供的绿色免安装版本，解压即可用。

```powershell
# 创建目录并下载
New-Item -ItemType Directory -Force -Path "bin\python"
Invoke-WebRequest -Uri "https://mirrors.tuna.tsinghua.edu.cn/python/3.13.9/python-3.13.9-embed-amd64.zip" -OutFile "bin\python.zip"

# 解压到 bin/python
Expand-Archive -Path "bin\python.zip" -DestinationPath "bin\python" -Force
Remove-Item "bin\python.zip"
```

**做了什么**：把 Python 运行时放到 `bin/python/python.exe`，不写入注册表、不依赖系统环境变量，完全绿色。

---

### 步骤 2：启用 `site` 模块

嵌入版默认禁用了 `site` 模块，导致 `site-packages` 不会被加载，pip 也无法正常工作。

修改 `bin/python/python313._pth`：

```
python313.zip
.

# Uncomment to run site.main() automatically
import site          ← 取消注释
```

**做了什么**：让 Python 启动时自动执行 `site.main()`，从而识别 `Lib/site-packages` 目录。

---

### 步骤 3：安装 pip

嵌入版不带 pip，需要手动安装：

```powershell
Invoke-WebRequest -Uri "https://bootstrap.pypa.io/get-pip.py" -OutFile "bin\python\get-pip.py"
bin\python\python.exe bin\python\get-pip.py --no-warn-script-location
Remove-Item "bin\python\get-pip.py"
```

**做了什么**：把 pip 安装到 `bin/python/Lib/site-packages/pip/`，使其成为纯 Python 包，不依赖外部系统。

---

### 步骤 4：移除硬编码的 `Scripts/pip.exe`

pip 安装时会生成 `bin/python/Scripts/pip.exe`，这个 exe 是一个 launcher stub，内部**硬编码了当前电脑的绝对路径**（如 `F:\1\ai-novelist\bin\python\python.exe`）。如果把这个目录复制到另一台电脑，路径不同，`pip.exe` 就会失效。

```powershell
Remove-Item -Recurse -Force "bin\python\Scripts"
```

**做了什么**：删掉所有含绝对路径的 `.exe` wrapper，保留纯净的 `Lib/site-packages/pip/`。

之后**永远不再调用 `pip.exe`**，而是使用：
```
python -m pip
```
这直接调用 `site-packages/pip/__main__.py`，没有任何硬编码路径。

---

### 步骤 5：修改 Go 启动器逻辑

**`backend/backend.go` 改动：**

1. **删除 `EnsureVenv`**：不再创建虚拟环境
2. **`PipInstall` 改用 `--target`**：
   ```go
   targetDir := filepath.Join(projectPath, "site-packages")
   installArgs := []string{"-m", "pip", "install", "-r", reqFile, "--target", targetDir}
   ```
   依赖被安装到 `<项目根目录>/site-packages/`，而不是 venv 内部。
3. **`Start` 注入 `PYTHONPATH`**：
   ```go
   cmd.Env = append(os.Environ(), fmt.Sprintf("PYTHONPATH=%s", targetDir))
   ```
   启动后端进程时，通过环境变量告诉 Python 去哪里找已安装的包。

**`launcher/launcher.go` 改动：**

删除 `backend.EnsureVenv` 调用，直接使用便携 Python 路径：
```go
// 旧：先建 venv，再用 venvPython 安装
venvPython, err := backend.EnsureVenv(projectPath, pythonPath, logger)
backend.PipInstall(projectPath, venvPython, pipMirror, logger)

// 新：直接用便携 Python 安装
backend.PipInstall(projectPath, pythonPath, pipMirror, logger)
```

## 二、`.venv` vs `--target + PYTHONPATH` 的区别

| 维度 | 虚拟环境（.venv） | `--target` + `PYTHONPATH` |
|------|------------------|--------------------------|
| **原理** | 复制一份 Python 解释器到 `venv/Scripts/`，隔离系统环境 | 使用同一个便携 Python，通过环境变量指定额外包搜索路径 |
| **路径依赖** | venv 内部的 `pyvenv.cfg` 和 `.exe` 会记录原始 Python 的绝对路径 | 只有环境变量是动态的，不含任何写死的绝对路径 |
| **跨电脑复制** | ❌ `venv` 复制到其他电脑后，内部路径失效，需要重建 | ✅ `site-packages/` 目录复制到任何地方，只要配好 `PYTHONPATH` 就能用 |
| **磁盘占用** | 两份 Python（原版 + venv 复制版） | 只有一份 Python，依赖放在外部目录 |
| **启动速度** | 额外一次 venv 创建过程 | 无需创建，直接安装 |
| **隔离性** | 完全隔离（venv 有自己的 site-packages） | 共享同一个 Python 标准库，但第三方包通过 `PYTHONPATH` 隔离 |

## 三、为什么要改用后者

**根本原因：便携分发。**

这个项目是给 Windows 用户打包分发的。用户使用时会：
1. 把安装包解压到任意位置（如 `D:\MyTools\ai-novelist`）
2. 直接运行启动器

如果用了 venv：
- venv 创建时会在 `pyvenv.cfg` 里记录 `"home = F:\1\ai-novelist\bin\python"`
- 用户解压到 `D:` 盘后，venv 仍然指向 `F:`，导致无法启动
- 必须在用户电脑上重新创建 venv，增加首次启动时间和失败风险

改用 `--target + PYTHONPATH` 后：
- 便携 Python 本身不记录任何绝对路径（嵌入版特性）
- `site-packages/` 只是普通的包目录，复制到任何位置都有效
- 启动器在运行时动态设置 `PYTHONPATH`，路径由代码根据 `projectPath` 计算，永远正确
- 整个目录可以任意移动、复制、分享，无需重新安装任何东西

这是因为你们使用了 `--target` 参数。

看 [`backend.go`](launcher/internal/backend/backend.go:32) 里的命令：

```go
installArgs := []string{"-m", "pip", "install", "-r", reqFile, "--target", targetDir}
```

**`--target` 的行为特性：**

1. **不做"已安装"检查**  
   正常 `pip install` 到虚拟环境时，pip 会读取 `site-packages` 里的 `.dist-info` 元数据，发现版本已满足就跳过（显示 `Requirement already satisfied`）。  
   但 `--target` 是为"打包/分发"场景设计的（比如 AWS Lambda、PyInstaller），pip 默认**不会**读取目标目录里的已有包来判断是否需要跳过，而是直接重新下载并覆盖。

2. **每次重新解析依赖图**  
   即使包还在 pip 的 HTTP 缓存里（下载快一点），它仍然会重新执行解压、复制、写入 `.dist-info` 的完整安装流程，所以你会看到完整的输出日志和等待时间。

3. **与虚拟环境的本质区别**  
   虚拟环境有完整的 `sys.path` 和元数据索引，pip 知道"环境里有什么"。`--target` 只是往一个普通文件夹里扔文件，pip 不把它当作一个"已管理的环境"。

**为什么你们用 `--target` 而不是虚拟环境？**

因为你们的架构是"便携版 Python + 外部 `site-packages` 目录"：
- Python 解释器是 `bin/python/python.exe`
- 依赖放在项目根目录的 `site-packages/` 里
- 通过 `PYTHONPATH` 指向这个目录来加载依赖

这种方式避免了用户机器上需要提前装 Python 或创建 venv，代价就是损失了 pip 的增量安装能力。

**现在的修改已经解决了这个问题：**

我们把安装和启动拆开了：
- 默认启动不再执行 `pip install`
- 用户只在需要时（初次部署、引入新依赖）手动点击"下载依赖"按钮

这样日常启动就快了，只有确实需要更新依赖时才触发一次完整的 `--target` 安装。
