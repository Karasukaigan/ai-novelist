## 启动器的 Git "切换版本" 工作原理

启动器的 Git 管理页面有两个操作路径：

### 1️⃣ UI 上点击「切换到该版本」→ [`GitCheckout`](launcher/app.go:279) → [`CheckoutCommit`](launcher/internal/gitman/gitman.go:221)

核心代码（[`gitman.go:221-241`](launcher/internal/gitman/gitman.go:221)）：

```go
func CheckoutCommit(projectDir string, hash string) error {
    // ...
    w, _ := repo.Worktree()
    err = w.Reset(&git.ResetOptions{
        Mode:   git.HardReset,   // <-- 硬重置
        Commit: h,
    })
    // 没有调用 Clean！
    return nil
}
```

**只执行了 `git reset --hard <commit>`**，等价于命令行：

```
git reset --hard <目标commit>
```

**效果分析：**

| 文件类型 | 会不会被删？ | 原因 |
|---|---|---|
| **被 Git 跟踪过的文件**（在后续 commit 中新增的） | ✅ **会删除** | `git reset --hard` 会让工作区完全匹配目标 commit 的文件状态，后续 commit 中新增的文件会从工作区消失 |
| **从未被 Git 跟踪的文件**（新建后没 add/commit 过的） | ❌ **不会删除** | `git reset --hard` 不处理 untracked 文件，这些文件会留在原地 |

### 2️⃣ HTTP API 的 [`RestoreCheckpoint`](launcher/internal/gitservice/gitservice.go:231)

这个路径**额外调用了 `Clean`**（[`gitservice.go:259-264`](launcher/internal/gitservice/gitservice.go:259)）：

```go
err = w.Reset(&git.ResetOptions{Mode: git.HardReset, Commit: hash})
err = w.Clean(&git.CleanOptions{Dir: true})  // <-- 额外清理
```

等价于：

```
git reset --hard <目标commit>
git clean -fd          # 删除所有未跟踪的文件和目录
```

**但 UI 的「切换到该版本」不走这个路径**，它走的是上面的 `CheckoutCommit`。

---

## 结论

| 操作 | 多出的已跟踪文件 | 未跟踪文件（新建未提交） |
|---|---|---|
| UI「切换到该版本」 | ✅ 自动删除 | ❌ **保留，不会自动删** |
| 切分支（Force checkout） | ✅ 自动删除 | ❌ 保留，不会自动删 |
| HTTP API RestoreCheckpoint | ✅ 自动删除 | ✅ 也会清理掉 |

所以如果你回档到一个旧版本，那些**之前提交过**的文件会消失；但如果你在工作区里**新建了文件但从未提交过**，它们会留在原地，不会被自动清理。

> **⚠️ 建议注意：** 如果你在工作区有未提交的新文件，回档后它们依然存在，但这些文件对应的目录或引用环境可能已经不在了（比如配置文件引用了不存在的模块），可能导致项目运行异常。回档前最好先确保工作区干净。
